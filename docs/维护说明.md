# Susu 网站维护说明

状态：复用文档 reusable。适用于本人或接手维护的开发者。

## 日常更新

1. 打开 https://susu5.cn/admin/ ，使用网站所有者的 GitHub 账号登录。
2. 编辑项目、知识库、图片、个人资料或首页装扮。保存草稿只影响后台。
3. 检查预览后发布当前条目。其他草稿不会一起发布。
4. 等待后台确认线上版本更新；必要时刷新前台。发布失败请先查看后台提示和 GitHub Actions，避免重复点击。

## 备份和恢复

重大修改、批量删除或迁移前，先在「备份与恢复」导出 ZIP。包内应有 manifest.json 和引用的图片文件，保留原始 ZIP，不手改内容。备份含私人草稿，不要上传到公开仓库。

建议每周保存一份，并在重要更新后补一份。浏览器出现“备份包已生成”仅表示已发起下载，请在下载列表确认 ZIP 实际保存成功。可以在“从本地备份恢复”选择刚下载的 ZIP，只做离线校验并查看数量；不点击恢复确认就不会改动后台内容。另存一份到自己控制的外置硬盘或私有云盘，避免电脑损坏后丢失。

导入后先查看内容数量和时间，选择恢复草稿版本或已发布版本。恢复会写入草稿，当前线上内容继续保留；确认项目、知识库、图片、个人资料和首页配置后，再发布需要更新的项目。

历史恢复用于撤销保存或找回删除前的内容，历史记录有限。恢复前当前状态也会留存快照。新功能上线前的历史不会被凭空补齐；旧的已发布版本仍可从 GitHub 历史核对。

完整内容备份不包含 GitHub App 密钥、登录会话、云账号配置。它可以用于迁移内容，不能单独恢复管理员登录；独立后台部署手册会说明重新配置方法。

## 网站代码更新

前台为原生 HTML、CSS、JavaScript，任何普通编辑器都可维护。建议改动通过分支和 Pull Request 检查，通过后再合并 main。GitHub Actions 在发布前检查数据和代码，失败不会覆盖线上网站。

在本地安装 Node.js 24 和 Git，克隆网站仓库后执行：

```sh
node --test scripts/validate-site.test.mjs scripts/admin-api.test.cjs scripts/admin-backup.test.cjs
node scripts/validate-site.mjs
```

检查成功后提交代码。无需 Codex、Sites 插件或特定电脑目录。

## 发布失败与回退

- 后台连接失败：检查登录状态与后台服务，未保存内容先复制到本地。
- 已提交但网站未更新：查看 GitHub 仓库 Actions 中 `Check and publish website` 对应提交，打开失败步骤。
- 图片引用检查失败：恢复缺失文件或在后台重新上传、保存并发布，不要跳过检查。
- 需要撤销代码改动：在 GitHub 使用 Revert 创建新的回退提交，并让检查和发布重新运行。
- 需要撤销内容改动：优先用后台历史恢复到草稿后再发布。只回退 GitHub 中的 content.json 不会同步后台，下次发布可能覆盖手工回退。

仓库 Actions 页面可重跑失败任务。后台服务停止时，前台通常仍能展示已发布的静态内容，但不能因此认定后台也已恢复。

## 账号和维护记录

域名续费、GitHub、Cloudflare 账号应由网站所有者控制，恢复方式保存在本人密码管理器。不要把密钥写入仓库或聊天记录。

每次重要升级记录日期、代码提交、数据版本、备份位置、验证结果和待办。修改依赖版本前先运行测试，在测试环境检查登录、保存、上传、发布和恢复流程。升级失败时保留当前生产版本。

迁移验收必须包含：新浏览器登录、保存草稿、上传图片、发布到 susu5.cn、核对线上版本，以及从真实备份恢复一次。未完成独立账号接入和这项演练前，现有服务不得下线。
